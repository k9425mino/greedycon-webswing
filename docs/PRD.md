# 손목 웹슈터 웹스윙 게임 — PRD

작성일: 2026-09-10 · 상태: 구현 전 요구사항 기준안

기술 설계: [ARCHITECTURE.md](./ARCHITECTURE.md)

## 1. 목적과 현재 작업 범위

프로그래밍 동아리 부스 방문객이 스마트폰을 장착한 손목으로 거미줄을 쏘고, 한국풍 거리의 건물 사이를 날아가는 1인칭 웹게임을 기획한다. 노트북에서 게임을 실행하고 외부 모니터로 플레이와 기록을 보여준다. 손동작과 화면 반응의 연결, 스윙의 관성과 속도감이 핵심 체험이다.

현재 센서·터치·연결·정면 보정, 무한 도로의 스윙 물리, 생존 시간 점수와 추락·정체 종료, 재시작이 구현되어 있다. 한국풍 표현과 로컬 기록은 아직이다. [구현 현황](IMPLEMENTATION.md)을 참고한다. 아래 구현 범위와 검증 기준은 전체 게임을 위한 명세이며, 게임 구현·배포·실기기 검증이 완료되었다는 의미가 아니다.

후속 개발 목표는 첫 주 안에 연결부터 플레이, 종료, 재시작까지 가능한 핵심 버전을 만드는 것이다. 팀은 얕은 풀스택 경험과 여러 차례의 AI 에이전트 활용 개발 경험이 있다. 실제 개발 인원, 투입 시간, 행사 날짜, 장비 사양은 미확정이다.

## 2. 결정 상태

| 구분 | 내용 |
|---|---|
| 사용자 확정 | 한 손·1인칭, 스마트폰 터치 화면을 중지·약지로 눌러 발사·유지하고 떼어 해제 |
| 사용자 확정 | 시작할 때만 전방 추진력 제공, 이후 물리 기반 스윙으로 이동 |
| 사용자 확정 | 부착 순간 스윙을 보조하는 작은 당김, 넉넉한 조준 보정, 전방 카메라 |
| 사용자 확정 | 무한 직선 도로, 생존 시간 점수, 전진 정체 시 종료, 건물 충돌 시 약한 반사 |
| 사용자 확정 | iPhone·Android 모두 지원 목표, 한국풍 거리 또는 학교 상징 건물 |
| 설계 기본값 | 추락 시 종료, 줄 하나만 사용, 공용폰 기본 운영, 개인폰도 같은 QR로 접속 |
| 설계 기본값 | 한국풍 반복 건물을 먼저 제작하고 학교 건물·VR은 후속으로 분리 |
| 설계 기본값 | 닉네임 기반 로컬 상위 10개 기록, 정체·점수 수치는 아래 초기값 사용 |
| 미검증 | 손목 장착 상태에서 터치와 조준을 동시에 수행할 수 있는지, 센서 호환성과 통신 지연 |

## 3. 대상 사용자와 체험 흐름

- 방문객: 짧은 설명을 듣고 조작을 익히는 초보 플레이어.
- 관람객: 외부 모니터에서 비행과 기록 경쟁을 지켜보는 사람.
- 운영자: 장비 장착, 연결, 정면 보정, 시작·복구·재시작을 도와주는 동아리원.

기본 흐름은 다음과 같다.

1. 운영자가 노트북에서 게임을 열고 연결용 QR을 표시한다.
2. 스마트폰으로 접속하고 시작 버튼을 눌러 필요한 센서 권한을 허용한다.
3. 폰을 손바닥 쪽 손목에 고정한다. 폰 상단은 손가락 쪽을 향하게 하는 배치를 먼저 시험한다.
4. 방문객이 정면을 가리키고 손가락을 화면에서 뗀 상태에서 운영자가 보정한다.
5. 짧은 조작 안내 후 운영자가 시작한다. 높은 위치에서 초기 전방 속도를 받고 비행한다.
6. 손목으로 부착점을 겨누고 터치를 유지해 스윙한다. 손가락을 떼어 관성으로 날아가고 다시 발사한다.
7. 추락하거나 전진이 정체되면 종료한다. 점수와 종료 이유를 보여주고 선택적으로 닉네임을 기록한다.
8. 운영자가 재시작하거나 다음 방문객을 위해 보정한다.

## 4. MVP 요구사항

### 4.1 입력과 조준

- **IN-01:** 스마트폰 한 대가 방향 센서와 터치 버튼 역할을 맡는다. 손의 공간상 위치나 손가락 모양을 추적하지 않는다.
- **IN-02:** 발사 영역에 손가락 하나 이상이 닿으면 누름, 모두 떨어지면 해제한다. 중지·약지 중 하나만 먼저 떨어져도 줄은 유지한다.
- **IN-03:** 한 번 누를 때 줄 하나를 발사한다. 유지 중 반복 발사하지 않는다. 빗나가거나 취소되면 손가락을 떼고 다시 눌러야 한다.
- **IN-04:** 기준 자세에 대한 폰의 상대 회전으로 조준한다. 카메라는 도로 전방을 유지하고 손목으로 화면 전체를 회전시키지 않는다.
- **IN-05:** 건물에 직접 맞는 조준을 우선하고, 빗나가면 조준 방향 근처의 도달 가능한 부착점으로 보정한다. 벽 뒤의 가려진 부착점은 선택하지 않는다.
- **IN-06:** 발사 전에 선택된 부착점을 표시한다. 유효 표적이 없으면 조준점 형태·색으로 알린다.
- **IN-07:** 터치 취소, 화면 전환, 센서 권한 거부를 처리하고 운영자가 복구 방법을 알 수 있게 한다.

### 4.2 스윙과 충돌

- **PH-01:** 시작할 때만 초기 전방 속도를 제공한다. 이후 지속 전진력이나 시간에 따른 자동 가속은 없다.
- **PH-02:** 중력·관성·충돌과 최대 줄 길이 제약을 적용한다. 줄이 느슨하면 자유롭게 움직이고, 팽팽하면 고정 부착점을 중심으로 스윙한다.
- **PH-03:** 부착 시점의 거리로 줄 길이를 고정한다. 자동 줄 감기와 손목 움직임에 의한 줄 길이 조절은 없다.
- **PH-04:** 새 부착에 성공한 순간에만 부착점 방향으로 작은 추진력을 한 번 적용한다. 실제 물리 위에 추가하는 게임 보조 효과임을 구분한다.
- **PH-05:** 줄 해제 시 현재 속도를 보존한다. 이후에는 중력과 충돌의 영향을 받는다.
- **PH-06:** 건물에는 약하게 튕긴다. 도로 바닥에 닿으면 종료한다. 건물 지붕은 건물 충돌로 처리하며 정체 규칙은 계속 적용한다.
- **PH-07:** 거미줄의 건물 모서리 감김과 거미줄 자체의 충돌은 MVP에서 제외한다.

### 4.3 월드, 점수와 종료

- **GM-01:** 도로 양옆에 건물이 이어진다. 앞으로 새 구간을 생성하고 멀어진 구간을 회수해 끝없이 진행할 수 있다.
- **GM-02:** 단순한 건물, 한글 간판, 차선으로 한국 거리 분위기를 만든다. 첫 버전에 학교의 정확한 지형·배치를 요구하지 않는다.
- **GM-03:** 실제 진행 중인 생존 시간으로 점수를 계산한다. 안내·준비·일시 정지·결과 화면 시간은 제외한다.
- **GM-04:** 도로 전방의 최고 도달 위치가 충분히 갱신되지 않으면 경고 후 종료한다. 뒤로 갔다가 같은 위치로 돌아오는 동작은 새 전진으로 인정하지 않는다.
- **GM-05:** 점수, 정체 경고, 종료 이유를 표시한다. 속도는 보조 HUD로 표시한다.
- **GM-06:** 결과에서 닉네임을 선택적으로 입력한다. 노트북 브라우저에 상위 10개를 저장하고 동점이면 먼저 기록한 항목을 앞에 둔다. 온라인 통합 랭킹은 없다.
- **GM-07:** 운영자가 한 번의 재시작 조작으로 새 게임을 준비한다. 새 게임에서는 위치·속도·줄·점수·정체 타이머를 초기화한다.

### 4.4 부스 운영과 복구

- **OP-01:** 데스크톱 세션 하나에는 활성 컨트롤러 하나만 연결한다. 두 번째 폰이 기존 플레이를 빼앗지 않게 한다.
- **OP-02:** iPhone Safari와 Android Chrome을 지원 대상으로 삼는다. 모든 기종 지원을 보장하지 않으며 실제 검증 기종을 추후 기록한다.
- **OP-03:** 부스 기본은 검증한 공용폰이다. 개인폰도 접속 가능하나 동일한 권한·장착·보정 절차를 거친다.
- **OP-04:** 연결 중단이나 입력 중단 시 물리·점수·정체 타이머를 함께 정지한다. 복구 후 터치 해제와 보정을 확인하고 운영자가 재개한다.
- **OP-05:** 폰 핫스팟과 인터넷 중계 서버를 사용할 수 있게 설계한다. 행사장의 실제 인터넷 품질은 사전 확인한다.

## 5. 제안 초기값과 검증 기준

아래 수치는 사용자 확정값이나 측정 결과가 아니다. 구현 시 한 설정 모듈에서 관리하고 실제 플레이 후 조정한다.

| 항목 | 제안 초기값 또는 목표 |
|---|---|
| 점수 | 진행 시간 0.1초당 1점 |
| 정체 초기화 | 이전 정체 기준점보다 전방 최고 도달 위치가 5m 증가할 때 |
| 정체 경고 / 종료 | 마지막 초기화로부터 5초 / 8초 |
| 입력 중단 판정 | 마지막 유효 입력으로부터 0.5초 |
| 방향·누름 상태 전송 | 최대 30Hz, 누름·해제 전환은 즉시 |
| 물리 계산 | 고정 60Hz |
| 화면 | 실제 노트북에서 60fps 목표, 30fps 미만이 지속되면 품질 조정 |
| 입력 반응 | 실제 핫스팟 환경에서 손동작부터 화면 반응까지 100ms 이내 목표 |

완료 판정은 다음을 포함한다.

1. 실제 iPhone과 Android 각각에서 권한 허용, 장착, 상대 방향 보정, 두 손가락 터치 유지·해제를 확인한다.
2. 초보자 3명이 짧은 안내 후 발사·유지·해제를 이해하고 연속 스윙에 성공한다. 실패 시 원인을 기록하고 조준·물리 값을 조정한다.
3. 새 부착에서만 당김이 한 번 적용되고, 줄 해제 후 속도가 보존된다. 건물 관통이나 줄이 느슨할 때의 강제 밀어내기가 없다.
4. 제자리 매달리기와 이미 지난 구간 왕복으로 정체 판정을 회피하지 못한다.
5. 연결 중단과 폰 화면 전환 중 점수가 증가하지 않고, 복구 후 눌림 상태가 남아 자동 발사하지 않는다.
6. 외부 모니터·실제 네트워크로 20분 연속 실행 및 10회 재시작을 수행한다. 객체 수와 메모리가 실행 시간에 비례해 계속 증가하지 않는다.

## 6. 우선순위와 미확정 사항

| 우선순위 | 내용 |
|---|---|
| P0 | 실기기 장착·센서·터치, 연결, 스윙 물리, 조준 보정, 종료·재시작, 연결 복구 |
| P1 | 한국풍 거리 표현, 로컬 기록, 속도감·거미줄·소리 연출 |
| 후속 | 학교 상징 건물 1~2개, VR |
| MVP 제외 | 양손 독립 거미줄, 온라인 멀티플레이, 계정·통합 랭킹, 실제 학교 배치 전체 재현 |

첫 검증은 그래픽 제작 전 손목 장착과 터치·조준 동시 사용이다. 불가능하면 장착 또는 입력 방식에 대한 사용자 결정을 다시 받아야 한다. 임의로 물리 버튼이나 제스처 입력으로 바꾸지 않는다.

미확정 사항은 테스트폰 기종, 노트북 GPU·해상도, 장착 도구, 행사 네트워크, 개발 인원·시간이다. 후속 구현 시작 시 확인하고 검증 기록을 남긴다. 일정이 부족하면 P1과 후속 항목부터 줄인다.
